# 591 競品分析

貼一個 591 物件詳情頁網址，抓社區行情資料（在售間數、成交均價、房型分布、
實價登錄樣本）**加上同社區實際在售的個別競品清單**，產生一份 HTML 報告：
一份給自己判讀用，一份是可以截圖／列印給屋主看的乾淨版本。

只做兩件事——不會做第三件：讀你貼的那一頁，再用社區名在 591 主站搜一次看結果頁。
**不會自己去爬社區以外的頁面，不會逐筆點開結果裡每一筆再查。**

---

## 為什麼是這個做法

591 物件頁的頁尾寫明「不得使用網路爬蟲或自動下載程式，違者按刊登物件收 3,000 元」，
跟 591 自動填表當初考慮的是同一類條款風險——只是這次是讀別人公開顯示的資料，
不是填自己的表。這件事已經跟本人講過、本人選擇沿用跟 591 自動填表一樣的做法：

1. **最多兩頁，不會更多。** 你貼的那一頁 + 用社區名搜一次的結果頁。沒有網址清單、
   沒有批次迴圈，不會自己點進結果裡每一筆去查，也不模擬捲動／翻頁把 237 筆抓完——
   結果頁只拿打開當下已經渲染出來的那三十筆左右，報告裡會誠實寫「找到 N 筆，顯示 M 筆」。
2. **用真的 Chrome、看得到畫面。** 跟你自己開瀏覽器看一頁沒有本質差異。
3. **只讀頁面本來就攤開給人看的內容**，不額外登入。

⚠️ **不要把這支腳本改成排程、批次跑一串網址**——那已經超出當初評估過的風險範圍，
跟「自己偶爾查一筆」是完全不同的兩件事。

會開一個 Chrome 視窗，終端機問你要分析哪個 591 物件網址，貼上（要詳情頁網址，

## 報告內容

1. **標的物件**：標題、價格、單價、格局／屋齡／權狀坪數／樓層／朝向／社區／地址
2. **社區行情總覽**：
   - **同社區在售競品**——實際個別物件清單，照總價由低到高排：標題（連回它自己的
     詳情頁）／格局／樓層／權狀坪／總價（含「降 X 萬」）／單價／標籤。這是真正拿來
     比較的「競品」，不是統計數字。
   - **重複刊登會標出來**：同樓層＋同權狀坪（比到小數一位）＋同總價視為同一戶，
     同一組用同一個字母標（重複A×2、重複B×3…），標題列寫「去重後 N 戶」。
     591 上同一戶被三四家仲介各刊一筆是常態，不去重的話「在售 237 間」會被高估。
   - 目前在售幾間、近半個月上架幾間、降價幾間、同房型成交均價、房型分布統計、
     實價登錄樣本，附 591 原始連結方便深入查
3. **屋主溝通版**：上面資料的濃縮卡片，帶「房仲蕭邦」署名，設計成適合截圖或列印。
   **只放 591 已公開顯示的數字，不生成漲跌或訂價建議**——那是要跟屋主當面談的事，
   這份報告只負責把行情攤在桌上，不替你做判斷。

有抓不到的欄位會在終端機列出來、報告裡留空，**不會用猜的**。

⚠️ 競品表**刻意沒有經紀人／公司欄**，程式從源頭就不收這個欄位——本人 2026-09-14
拍板：報告（含內部版）一律不秀其他仲介的名字。

⚠️ 競品表的單價＝總價 ÷ 含車位權狀坪（591 清單頁的算法，跟本件的 591 單價同一套）；
實價登錄的單價是扣掉車位算的，**兩邊不能直接互比**，報告表格下面有註明。

## ⚠️ 591 有一招反爬蟲，改版時要注意

社區在售房型的坪數（例如「三房 42~65坪」）不是一般文字，591 用一堆
`<i style="order:N">單一字元</i>` 拼出來，**DOM 出現順序跟畫面顯示順序故意不一樣**
——肉眼看沒事，單純照 DOM 順序讀字串會讀出錯的數字（實測讀到「24坪」，
畫面實際顯示、也合理的是「42坪」）。

`extract.mjs` 的 `readOrdered()` 會照 `style.order` 排序後再拼字，等於照人眼實際
看到的做。591 改這招的細節（例如換一個 CSS 屬性）的話，`test-extract-logic.mjs`
會先炸，去看那個測試怎麼壞的，再回來調 `readOrdered()`。

## ⚠️⚠️ 總價／坪數／樓層是從搜尋頁的純文字來的，不是破解 `<wc-obfuscate-price>` 來的

2026-08-25 到 09-14 之間，同社區在售清單讀的是 market.591.com.tw 的社區清單頁。
那一頁 591 用自訂元素 `<wc-obfuscate-price{id}>`／`<wc-obfuscate-area{id}>`／
`<wc-obfuscate-floor{id}>` 把每筆物件的總價、坪數、樓層直接藏起來——**元素裡面根本
沒有文字內容**，不是排序詭計，是真的不給程式讀。元件名稱直接寫著 "obfuscate"，
591 的意圖沒有模糊空間，繞過它不是「工具做得更好」，是跨過「讀公開頁面」到
「破解防護」的線。**那一頁我們從頭到尾沒有去繞它。**

2026-09-14 本人要求競品表要有每戶的實際售價、要標出重複刊登——這兩件事都需要
總價與坪數樓層。解法不是回頭研究怎麼繞，而是**換一頁讀**：591 主站的關鍵字搜尋頁
（`sale.591.com.tw/?region=8&keywords=社區名`）本來就用純文字把總價
（`.ware-item__price-value`）、權狀坪、樓層（`.ware-item__attr`）排給人看，
讀它跟人打開瀏覽器看沒有差別。現在 `extractSearchComps()` 讀的是這頁，
market.591.com.tw 那頁不讀了（報告裡只留連結）。

**如果哪天搜尋頁也開始 obfuscate，做法一樣：留白、附連結，不要去研究怎麼繞。**

⚠️ 搜尋頁要帶縣市代碼（`region=`），不帶會預設搜台北市。縣市代碼表在
`_shared.mjs` 的 `REGION_IDS`，是從 591 縣市選單的連結逐筆抄的，不是憑印象。
另外 591 同一個社區名會混用「悅／悦」，`normalizeCommunityName()` 會統一再比對；
社區名對不上時用「行政區＋路名」當備援，兩個都對不上的卡片一律丟掉（搜尋結果會
混進建案廣告跟別區的推薦物件）。

## ⭐ 遇過一次：頁面主要區塊還沒 hydrate 完，讀到字面上的樣板文字

2026-08-25 實測遇到一次：社區資訊那個獨立元件已經渲染完成（在售間數等數字都對），
但頁面主要的標題／價格／規格那個元件還沒——這時候讀 `.detail-title-text` 讀到的
不是空字串，是**字面上的樣板語法**（例如整個字串就是 `${title}`）。這種內容比
「抓不到」更危險：它看起來像有值，不會觸發任何「抓不到」的警告，會被當成真資料
直接印進報告——如果沒接住，屋主溝通版卡片上可能出現 `${title}` 這種東西。

兩層接住：
1. `extract.mjs` 的 `text()` 對每一個讀出來的字串檢查是否含 `${`／`{{` 這類未渲染
   的樣板語法，含的話當成空字串（等同「抓不到」，會正常進 warnings）。
2. `analyze.mjs` 發現標題抓到空字串時，**不重新整頁**（那樣又是打一次 591），
   而是在同一個已經開好的頁面上等 1.5 秒再讀一次——通常這樣就夠了。

兩次實測跑同一個網址，第二次真的又遇到一次、也真的被重讀機制接住了，看起來是
591 這頁偶爾會有的正常波動，不是特例。

## 591 改版、資料抓不到了怎麼辦

1. 跑 `npm run analyze` 看終端機印出哪幾項在 warnings 裡
2. 打開同一個物件網址，看真實頁面現在長怎樣（右鍵→檢查）
3. 對照 `extract.mjs` 裡對應欄位的選取器，改成新的
4. 跑 `npm test`（見下面）確認邏輯測試還過

## 測試（591 改版後可以重跑驗證，不連網）

```bash
npm test
```

用 Playwright 開兩份存下來的真實頁面簡化版（`fixtures/sample-detail.html` 物件
詳情頁、`fixtures/sample-search.html` 主站搜尋頁），讓真正的 `extractListing()`
／`extractSearchComps()` 去抓，核對抓出來的值：DOM 亂序還原、搜尋結果過濾
（建案廣告與別區推薦要丟掉、「悅／悦」要對得上）、功能標籤過濾、不收經紀人姓名。
另外直接測 `_shared.mjs` 的純邏輯：地址拆縣市代碼、去重（含 38.71 vs 38.7 坪
這種四捨五入差異、同層鏡像戶不誤判）。
不碰真的 591，也不用等本人去複製貼上網址才能驗證程式邏輯有沒有壞。

## 檔案

| 檔案 | 做什麼 |
|---|---|
| `analyze.mjs` | 主程式：開瀏覽器 → 抓物件頁 → 用社區名搜同社區在售 → 去重 → 產生報告 |
| `extract.mjs` | 從已經開好的 591 頁面抽資料（`extractListing` 物件頁／`extractSearchComps` 搜尋頁，純邏輯，測試都測這個） |
| `render-report.mjs` | 把抽出來的資料變成 HTML 報告 |
| `_shared.mjs` | 共用：網址格式檢查、縣市代碼表、地址拆解、去重、讀 `OWNER` 品牌資料、終端機互動 |
| `fixtures/sample-detail.html` | 離線測試用的簡化真實物件詳情頁 |
| `fixtures/sample-search.html` | 離線測試用的簡化真實搜尋頁（含兩筆重複刊登、一張建案廣告、一筆別區推薦） |
| `test-extract-logic.mjs` | 對著兩份 fixture 跑，驗證抽取與去重邏輯 |
| `reports/` | 產生的報告（不進版控） |
