# 物件上架助手（Chrome 外掛）

貼上愛屋電子型錄（或自己打的物件文字，貼上就會自動解析，不用按按鈕）→ 補紅底的格子 → 按「上架到 591」或「上架到樂屋」，
外掛會開一個刊登分頁，把每一格、文案、照片自動填好。**「保存資料，下一步」「立即支付」「庫存」「上架」永遠由你自己按。**

- 只在 `user.591.com.tw/post/*` 和 `member.rakuya.com.tw/{sell,rent}/post/*`（刊登流程）動作，別的網站一律不理。
- 不抓這兩個網站任何資料、不存你的帳密、不連任何其他伺服器；你的姓名電話只存在自己的 Chrome 裡。
- 照片是從愛屋圖檔主機抓「你自己那一戶」的檔案塞進上傳框。
- 出售、出租都支援（貼租屋型錄會自動當出租處理）。
- ⚠️ **591 已對真實物件驗證過（見下面「對真實 591 實測」）；樂屋是 2026-09-12 剛做的第一版，還沒對真的樂屋網跑過**——
  欄位名稱、選項文字都是照「應該長這樣」寫的，第一次用一定要對著你自己登入的樂屋帳號實測，照面板紅字回頭調整。
- ⚠️ **固定尾段的樣式（字級／顏色）與「591＋樂屋一起上架」是 2026-09-15 新增的，還沒對真的 591／樂屋帳號測過**——
  邏輯與 HTML 巢狀順序都有自動測試涵蓋，但「貼上去 591 之後真的長那樣」要本人親自測一次才算數；沒設任何樣式就跟以前一樣貼純文字，行為不變。

## 安裝（只要做一次）

1. 這個資料夾（裡面直接看得到 `manifest.json`）就是外掛本體。**不要搬走、不要刪**；要給別台電腦用就整個資料夾複製過去。
2. Chrome 網址列輸入 `chrome://extensions` → Enter
3. 右上角把 **「開發人員模式」** 打開
4. 左上角 **「載入未封裝項目」** → 選這個資料夾
5. 清單出現「物件上架助手」、開關是開的 → 完成。建議釘在工具列：網址列右邊 🧩 → 找到它 → 📌
6. 先在 Chrome 登入 591 會員中心／樂屋會員中心（外掛不會幫你登入；哪個平台都要就兩個都登入）

## 第一次用：填自己的資料

點工具列的「物件上架助手」圖示 → 上方「⚙ 我的資料」填 **姓名、手機**（必填；姓名會變成 591 的聯絡人）、
LINE ID、經紀業名稱、委託書預設、描述抬頭，按「儲存」。
「固定尾段」選填：每一戶描述最後固定接的一段（電話、LINE、店名），`{{name}}` `{{phone}}` `{{line}}` `{{company}}` 會自動代換。
第一次解析型錄時，型錄上的「經紀人員／電話」會先幫你填進去，確認後按儲存就好。

「固定尾段的樣式」也選填：字級、**粗體**、底線整段共用，文字顏色和底色**一行一行各自選**（點色盤的色塊）。
只套在固定尾段，型錄的 ✨ 特色行維持純文字；④ 的描述下面會有「上架時長這樣」預覽，貼到 591／樂屋之後就長那樣。
⚠️ **591 不支援底線**（貼上去會被拿掉），樂屋看得到；沒設任何樣式就跟以前一樣貼純文字，行為不變。

描述裡「固定尾段」以外的每一行（抬頭＋✨ 特色行）**固定粗體＋18px，不用設定、也不能關**
（2026-09-24 起）——這條不算在「固定尾段的樣式」裡，是固定尾段以外全部內容的固定規則。

## 每一戶怎麼上

1. **最省事：直接貼型錄頁的網址**（一行就好）到「① 貼上資料」，**貼上就會自動解析**（不用按按鈕；想重新解析
   還是可以按「解析」），外掛會自動把型錄頁抓回來、連完整門牌都會帶（用這台電腦上 Chrome 本來就登入愛屋的狀態去抓，
   不會另外存密碼）、照片也自動帶，不用自己複製。
   如果這台電腦的 Chrome 沒登入過愛屋，門牌就會是空的——畫面會清楚告訴你「門牌沒帶到」，③ 自己補一下，或改用下面的 Ctrl+A 方式。
   也可以照舊：打開愛屋電子型錄，把地址旁的「**顯示**」點開（門牌才會帶進來）→ `Ctrl+A` → `Ctrl+C`
2. 點外掛圖示 → 貼到「① 貼上資料」→ 按「解析」（照片連結會一起帶進來，不用另外複製）
3. 看「③ 第②頁每一格」：**紅底** = 型錄沒有、要你補（最常見：裝潢程度）；任何一格覺得不對直接改
4. 「④ 標題與描述」可以改字；有敏感字（保證／最／增值／未通車捷運…）會標出來，只標不刪
5. 「⑤ 照片」：通常自動有；沒有的話把型錄頁網址或「更多照片」的連結（右鍵 → 複製連結網址）貼進去
6. 按「🚀 上架到 591」或「🏠 上架到樂屋」→ 跳到那個平台的刊登分頁自動填。**填的時候不要切到別的分頁**，等右下角面板出現「✅ 填完」。
   兩個平台都要上就按「🚀🏠 591＋樂屋一起上架」：會先開 591 填，591 填完自動接著開樂屋分頁填（不用自己等填完再手動點第二顆）。
7. 從上往下核對一遍（尤其門牌「樓」、車位型式、裝潢程度、照片張數），再自己按 591 的「保存資料，下一步」→「立即支付」、
   或樂屋的「庫存」（先存不上架）／「上架」。一起上架時兩邊都要各自核對、各自按。

也可以貼自己打的物件文字：第一行標題（或用「」包起來）、`地址：`、`售價：`或`租金：`／`押金：`、
`格局：3房2廳2衛`、`坪數：`、`主建：`、`公設：`、`樓層：12/15`、`屋齡：`、`社區：`、`管理費：`、`車位：`、`朝向：`、
✨ 開頭的特色行。沒寫的就留紅底給你補，不會猜。

## 常見狀況

| 狀況 | 怎麼辦 |
|---|---|
| 直接雙擊 `app.html`，按鈕都沒反應 | 那樣開會被瀏覽器擋住。要從 Chrome 工具列的外掛圖示打開 |
| 按了上架，591 分頁開了但什麼都沒填 | 多半還沒登入 591；先登入，再到 `chrome://extensions` 按這個外掛的 ↻，回操作頁重新整理再按一次 |
| 面板紅字「○○沒選到／沒找到」 | 那一格自己點一下就好，其他格照樣填好了；如果很多格都這樣，是 591 改版了（見下面） |
| 填到一半停住 | 分頁被切到背景了（Chrome 會把它放慢），點回來等它跑完；真的不動就關掉那個 591 分頁再按一次上架 |
| 上架鈕說要先填我的資料 | 姓名和手機是必填，回「⚙ 我的資料」填好按儲存 |

## 591／樂屋改版了、或欄位選不到怎麼辦

591 的填表程式是 `fill591.js`：標籤文字都集中在檔案最上面的 `T` 物件（「出售總樓層」「權狀坪數」這些字），
591 改了字就改那裡；結構變了（例如地址區長相不一樣）再改對應的函式。樂屋是 `fillRakuya.js`，欄位用 `name`
屬性定位（不是文字），改版時要重新對照真實表單的 `name` 屬性。改完到 `chrome://extensions` 按 ↻ 重新載入，
**記得看面板標題的版本號有沒有變**（改版本號是為了確認真的重載成功、不是還在跑舊版）。

面板會逐格報「沒找到」，把面板上的紅字貼給 Claude 就知道壞在哪；不確定是哪個欄位時，
對著那個欄位本身按右鍵「檢查」，點反白那一行、再按鍵盤「↑」往上跳一兩層看外層結構，截圖給 Claude
（比滑鼠在 DevTools 裡滾動準，也不會像 Console 貼上指令那樣撞到 Chrome 的安全警告）。

## 檔案

| 檔 | 做什麼 |
|---|---|
| `manifest.json` | 外掛設定（權限只有 storage；只碰 houseol／591／樂屋／cloudinary 四個網域） |
| `app.html` / `app.js` / `app.css` | 操作頁：貼 → 解析 → 每一格 → 標題描述 → 照片 → 上架（591 或樂屋二選一按鈕）；`app.js` 也放了封面貼圖合成（canvas，`compositeCoverPhoto()`） |

| `lib/address.js` | 地址拆成 縣市／鄉鎮／街道／巷／弄／號／之／樓／樓之（含中文數字樓層） |
| `lib/map591.js` | 結構化資料 → 591 每一格該填什麼、資料包（含 descHtml）、直接開第②頁的網址 |
| `lib/rakuya-map.js` | 591 資料包 → 樂屋要選哪個字（法定用途、屋齡分類、車位型式…）；**還沒對真樂屋驗證** |
| `lib/risk.js` | 文案敏感字（公平交易法）＋ Markdown 符號提醒 |
| `lib/tailStyle.js` | 固定尾段的樣式：字級／粗體／底線／每行顏色 → 591／樂屋都吃的 HTML（純函式） |
| `lib/floorplan.js` | 格局圖偵測的判斷邏輯（白色比例／灰階比例門檻、挑分數最高的一張，純函式）；`background.js` 用 `importScripts` 載入來解碼真的圖檔（跟 `license.js` 同一招） |
| `lib/parser.js` 的 `catalogTextFromHtml` | 型錄頁 HTML → 跟手動 Ctrl+A/Ctrl+C 一樣格式的文字，讓既有的解析規則原封不動吃（貼網址自動解析用） |
| `lib/launchQueue.js` | 「591＋樂屋一起上架」的資料包排隊邏輯正本（background.js 是 classic script，另外手寫一份跑在那邊） |
| `background.js` | 開分頁、保管資料包（591／樂屋各自一格）、一起上架的排隊/接力、跨網域抓照片與型錄頁、按上架後順手登記追蹤清單（見下面「上架物件追蹤」） |

## 對真實 591 實測踩到的坑（2026-09-11，已修）

第一次對真的 591 出租表單測試（商辦物件），發現兩個假表單測不出來的真實結構差異：

1. **地址寫中文數字樓層**（型錄「十三樓之２」不是「13樓之2」）——原本的地址解析只認阿拉伯數字，
   樓層整個抓不到，591 那格會空著，而且**不會有任何警告**（`lib/address.js` 已加中文數字轉換）。
2. **591 有些表單類別（例如商辦）把「樓」「樓之」拆到「地址」那一列的下一列**，跟「巷/號/之」不同一個
   區塊；原本的程式只找同一列，找不到就默默放棄、也不提醒。同一類表單的**街道下拉也沒有「填寫完整地址」
   快速框，選項要打字才會出現**，原本的程式只看畫面上已經 render 的選項，不會主動打字觸發搜尋
   （`fill591.js` 的 `controlsAcross()` 放寬到抓下一列、`pickSelect()` 加了打字觸發搜尋）。

`test/fixtures/catalog-rent-office-synthetic.txt` 照這次真實案例的欄位排法重建（門牌與物件編號已改），
`test/mock-591.mjs` 新增 `"office"` 版面模擬這兩個真實結構差異，`test-fill-e2e.mjs` 有專門的回歸測試。

## 要知道的規矩

591 服務條款禁止爬蟲與自動下載程式；性質類似的規範多半也適用樂屋。這個外掛只是把你自己的物件資料填進表單、
最後由你本人送出，性質上是輸入輔助；但「用程式操作表單」仍可能被平台視為自動化，一次上一戶、不要批次連發。
刊登內容的正確性與法規責任在刊登人自己，工具只負責把型錄的字搬過去。
