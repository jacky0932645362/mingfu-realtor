# 數位名片 ＋ 線上預約系統

> 客戶掃你的名片 → 自己挑時間 → 預約直接進你的 Google 日曆 → 雙方都收到通知信。
> 中間你一句話都不用回。

這是一套**正在營運中**的系統原始碼，不是教學範例。所有功能都是真的在跑、被真實客戶用過、
被真實問題打磨過的版本。

---

## 這套系統在解什麼問題

房仲最花時間的其實不是帶看，是**約時間**。

```
客戶：「你這禮拜有空嗎？」
你：「週三下午可以」
客戶：（三小時後）「不好意思週三我不行欸」
你：「那週四？」
客戶：（隔天早上）「週四幾點？」
```

一次約訪要來回七八則訊息，而且你還得記得寫進行事曆。忘記寫的那次，
就是你同時答應兩個客戶的那次。

這套系統把這段全部拿掉：**客戶自己看你的空檔、自己選、自己填資料**，
送出的瞬間進你的日曆，雙方各收一封確認信。

## 功能

### 前台（客戶看到的）

| | |
|---|---|
| **數位名片** `/card` | 照片、頭銜、一句話介紹、電話／LINE／社群一鍵打開 |
| **線上預約** `/card/booking` | 挑日期 → 挑時段（15 分鐘一格）→ 填資料 → 送出即成立 |
| **自助管理** `/card/booking/manage` | 客戶自己改期或取消，不用問你 |

預約表單會問：姓名、性別、電話、Email、**想談什麼**（買房／賣房／租屋／法律／其他）、
**急迫程度**（越快越好／這個月／先了解）、想約哪種形式（公司面談／電話／視訊）。

這些不是為了問而問 —— 你在見面前就知道對方要什麼、多急，可以先準備。

### 後台（你看到的）

| | |
|---|---|
| **預約總表** `/admin/appointments` | 誰、什麼時候、要談什麼、多急，一頁看完 |
| **改期／取消** | 後台直接動，客戶會收到通知信 |
| **自訂地點審核** | 客戶說「約在我家」時要你點頭才成立 |
| **日曆標題自訂** | 日曆上長什麼樣自己決定，不用改程式 |
| **送出頻率限制** | 防灌爆，被誤擋時一鍵解除 |
| **孤兒預約偵測** | Google 日曆上被刪掉、資料庫還在的，自動標紅 |

## 快速開始

### 1. 你需要什麼

- Node.js 20 以上
- 一個 MySQL 資料庫（[TiDB Cloud](https://tidbcloud.com/) 有永久免費方案，個人用夠了）

### 2. 裝起來

```bash
git clone <你 fork 的網址>
cd card-booking
npm install
cp .env.example .env.local
```

### 3. 填設定

打開 `.env.local`，**只有四個是必填的**：

```env
DATABASE_URL="mysql://..."          # 資料庫
APPOINTMENT_BASE_URL="http://localhost:3000"
APPOINTMENT_TOKEN_SECRET=""         # 隨便一組長亂數
APPOINTMENT_ADMIN_EMAIL=""          # 你的收信信箱
```

產生 `APPOINTMENT_TOKEN_SECRET`：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

其他（Google 日曆、寄信、防機器人）**不填也能跑**，只是那些功能關著。

### 4. 建資料表

```bash
npx prisma db push
```

只會建 `appointment` 一張表。其他 10 張（設定、通知佇列、速率限制、時段鎖…）
程式第一次用到時會自己建，你不用管。

### 5. 換成你自己的名片

打開 **`src/config/owner.ts`**，這是整套系統唯一需要改的設定檔：

```ts
export const OWNER = {
  name: "王小明",              // ← 換成你的名字
  alias: "小明",               // ← 客戶怎麼叫你
  title: "OO 房屋資深經紀人",   // ← 你的頭銜
  phone: "0900-000-000",
  email: "your-email@example.com",
  // ...
};
```

大頭照放 `public/card/owner.jpg`。

### 6. 跑起來

```bash
npm run dev
```

打開 http://localhost:3000/card 就是你的名片了。

## 上線

推到 [Vercel](https://vercel.com/) 最快，免費方案就夠：

1. 把這個 repo 連到 Vercel
2. 把 `.env.local` 裡的東西填進 Vercel 的 Environment Variables
3. `APPOINTMENT_BASE_URL` 記得改成正式網址

⚠️ **上線前一定要補的兩件事**

1. **Turnstile 防機器人**（`TURNSTILE_SECRET_KEY`）—— 不設的話會收到灌爆的假預約
2. **後台登入**（`AUTH_*`）—— 不設的話 `/admin/appointments` 沒有保護

## 幾個設計上的選擇，跟你說為什麼

這些都是踩過才改的，直接照抄可以少走一段。

### 預約送出就成立，不用去信箱點確認

原本有「15 分鐘內去信箱點確認連結」這關，用來擋假預約。

實際跑下來發現：**真客戶也會忘記點**。特別是手機填完就切走的人，
那筆預約就這樣消失了，而你永遠不知道有人想找你。

擋掉的假預約，遠不如漏掉的真客戶值錢。改成送出即成立，防機器人交給 Turnstile。

### 時段用 15 分鐘一格

一開始是 30 分鐘。但「電話諮詢」通常 15 分鐘就講完了，
用 30 分鐘一格會讓一個下午只能排四個人。

改成 15 分鐘起跳 + 可選時長，同一個下午的產能差很多。

### 客戶想約「自己指定的地點」要你點頭

客戶可以填「約在我家」「約在某某咖啡廳」，但**那筆預約不會直接成立**，
會進後台等你核准。

理由很現實：你不會想在完全不知情的狀況下，行事曆上多出一個陌生地址。

### 案件編號長成 `AP-260806-01`

原本是一長串亂數 id。改成看得懂的格式之後，
**你在電話裡可以直接念給客戶聽**，客戶也記得住。

### 日曆事件的標題自己設

原本寫死成「預約｜客戶姓名」。系統擁有者第一次看到自己日曆的反應是
「這什麼奇怪的名詞」——因為日曆是**你自己每天在看的東西**，
標題要用你習慣的講法。所以改成後台可設定。

### 通知信走「交易信」格式

一開始寫得很像行銷信（大圖、按鈕、標語），結果**掉進 Gmail 的促銷分頁**，
客戶根本沒看到。

改成精簡的純文字風格之後才進主要收件匣。預約確認信不是廣告，
它是客戶在等的東西，要讓它到得了。

## 專案結構

```
src/
├─ config/owner.ts          ← 🔴 你要改的就這一個
├─ app/
│  ├─ card/                 ← 前台：名片、預約表單、自助管理
│  ├─ admin/appointments/   ← 後台：預約管理
│  └─ api/appointment/      ← API：建立、時段查詢、改期取消、日曆、追蹤
└─ lib/
   ├─ appointment.ts                    核心邏輯（時段計算、衝突檢查、狀態流轉）
   ├─ appointment-constants.ts          可調參數（時段長度、營業時間、地點選項）
   ├─ appointment-notify.ts             通知信與 LINE 推播
   ├─ appointment-rate-limit-settings.ts 送出頻率限制
   ├─ appointment-calendar-display.ts   日曆標題與顏色
   └─ google-calendar.ts                Google 日曆整合
```

想調整營業時間、時段長度、可選地點 → 看 `src/lib/appointment-constants.ts`。
